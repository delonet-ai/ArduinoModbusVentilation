# ArduinoModbusVentilation

Прошивка управляет десятью сервоприводами вентиляционных заслонок с Wiren Board по Modbus RTU. Целевая плата — классический Arduino Nano на ATmega328P.

Поддерживаются два взаимоисключающих варианта подключения серв:

- `DIRECT` — сервы подключены непосредственно к пинам Nano;
- `PCA9685` — сервы подключены к внешнему 16-канальному PWM-контроллеру по I²C.

Backend выбирается при сборке. Modbus-интерфейс в обоих вариантах одинаков.

Для установки с десятью сервами рекомендуется `PCA9685` и отдельный источник питания серв. Прямой вариант проще и остаётся полезным для небольших установок и диагностики, но на Nano все импульсы формируются одним аппаратным таймером. PCA9685 освобождает пины и таймер Nano и продолжает выдавать PWM независимо от обработки Modbus. Сам по себе контроллер не увеличивает момент, скорость или точность механики.

## Modbus

- протокол: Modbus RTU slave;
- Slave ID: `128`;
- порт: `9600 8N1`;
- RS-485 DE/RE pin: `D2`;
- управляющие регистры: holding registers.

| Регистр | Канал | Значение |
| --- | --- | --- |
| `0` | `Kitchen` | кухня, приток и вытяжка, `0..100%` |
| `1` | `Cabinet` | кабинет, приток и вытяжка, `0..100%` |
| `2` | `Bedroom` | спальня, приток и вытяжка, `0..100%` |
| `3` | `Living` | гостиная, приток и вытяжка, `0..100%` |
| `4` | `Kid` | детская, приток и вытяжка, `0..100%` |
| `5..14` | внутренние `Applied_*` | применённые уставки десяти физических каналов |
| `15` | `Exhaust_total` | сумма применённых уставок вытяжки, `200..500%` |
| `16` | `Supply_total` | сумма применённых уставок притока, `200..500%` |
| `17` | внутренний `Safety_adjustment` | флаги защиты расхода |
| `18` | `Controller_ready` | `1` — выбранный servo backend работает |
| `19` | `Fireplace_mode` | `1` — кухня и гостиная по притоку принудительно открыты на `100%` |

Значения выше `100` ограничиваются прошивкой до `100`.

Регистры `0..4` и `19` доступны для записи. Регистры `5..18` диагностические; Arduino перезаписывает их актуальными значениями в каждом цикле.

## Защита расхода

Каждый комнатный регистр одновременно задаёт приток и вытяжку комнаты. Если сумма пяти комнатных положений меньше `200%`, недостающая величина автоматически добавляется сначала спальне, затем детской, после них кухне, кабинету и гостиной. Нормализованные значения сразу возвращаются в регистры `0..4`, поэтому ползунки WB всегда показывают реально применённое распределение. Ни один канал не поднимается выше `100%`.

В EEPROM сохраняются нормализованные комнатные значения. Чтобы уменьшить приоритетную спальню или детскую ниже автоматически выставленного уровня, сначала увеличьте одну из других комнат так, чтобы общая сумма оставалась не меньше `200%`, затем уменьшите нужную комнату.

## Режим камина

При значении `Fireplace_mode = 1` приточные клапаны кухни и гостиной принудительно открываются на `100%`. Остальные применённые положения не изменяются. После записи `0` оба клапана возвращаются к комнатным уставкам. Режим камина не сохраняется в EEPROM и после перезапуска Arduino выключен.

## Хранение положений

Рабочие положения сохраняются в EEPROM через две секунды после последнего изменения. Используются две записи с версией, номером последовательности и CRC, поэтому незавершённая запись не уничтожает предыдущую корректную.

При первом запуске прошивка переносит старый десятибайтовый формат, если все значения находятся в диапазоне `0..100`. При чистой или повреждённой EEPROM используется безопасное для вентиляции значение `100%`.

## Настройка импульсов

Безопасные физические границы задаются отдельно для каждого канала в `HardwareConfig.cpp`:

- `kServoMinPulseUs` — минимальный импульс;
- `kServoMaxPulseUs` — максимальный импульс.

Проверенные для этой механики значения — `400..2500 мкс`. Меняйте их только по документации сервопривода и после проверки механики заслонки.

## Прямое подключение

Порядок десяти физических каналов (сначала пять вытяжных, затем пять приточных):

`D8`, `D9`, `D10`, `D11`, `D12`, `A0`, `A1`, `A2`, `A3`, `A4`.

RS-485 модуль:

- `DI`/`RO` подключаются к аппаратному UART Nano (`TX`/`RX`);
- объединённые `DE` и `RE` подключаются к `D2`;
- GND Nano, RS-485 и питания серв должен быть общим.

## Подключение PCA9685

- `SDA` → `A4`;
- `SCL` → `A5`;
- адрес по умолчанию: `0x40`;
- частота PWM: `50 Гц`;
- сервы подключаются к каналам PCA9685 `0..9`: сначала пять вытяжных, затем пять приточных.

`VCC` PCA9685 питает только логику. Питание серв подаётся на силовую клемму `V+` от отдельного источника, рассчитанного на суммарный пусковой ток серв. Не питайте десять серв от вывода `5V` Nano. Земля внешнего источника, PCA9685, Nano и RS-485 должна быть общей.

В режиме PCA9685 встроенный LED горит, если контроллер не найден или произошла ошибка I²C. Прошивка продолжает обслуживать Modbus и повторяет инициализацию PCA9685 каждые пять секунд.

Линии `SDA` и `SCL` предназначены для короткого соединения внутри шкафа. Не прокладывайте I²C вместе с длинными кабелями к удалённым заслонкам: размещайте Nano и PCA9685 рядом, а на большое расстояние используйте RS-485. Силовые провода серв следует прокладывать отдельно от сигнальных линий Modbus и I²C.

## Питание серв

Независимо от выбранного backend сервы должны питаться от отдельной силовой линии:

```text
источник 5–6 В
  +-- предохранитель/распределитель -- питание серв 1..10
  +-- V+ PCA9685 (только для варианта PCA9685)
  `-- GND -- сервы -- PCA9685 -- Nano -- RS-485
```

- напряжение выбирайте по паспорту конкретных серв;
- ток источника рассчитывайте по сумме токов заклинивания всех серв, которые могут стартовать одновременно, с запасом 20–30%;
- не пропускайте силовой ток серв через Nano, USB, макетную плату или тонкие сигнальные дорожки;
- объединяйте земли около источника питания, не последовательно через Nano;
- для длинной силовой разводки используйте отдельные предохранители на каналы или группы и проверяйте падение напряжения на наиболее удалённой серве;
- ёмкость возле распределителя питания подбирайте по измерениям: напряжение не должно проседать настолько, чтобы перезапускались Nano или RS-485.

## Механика заслонок

- Подберите плечо рычага так, чтобы рабочий ход заслонки использовал значительную часть хода сервы. Слишком длинный рычаг увеличивает перемещение, но уменьшает доступное линейное усилие.
- Настройте `kServoMinPulseUs` и `kServoMaxPulseUs` отдельно для каждого канала с запасом до механических упоров. В крайних положениях серва не должна гудеть, греться или продолжать давить на упор.
- Исключите боковую нагрузку на вал сервы и закусывание тяги по всему диапазону движения.
- Проверьте, удерживает ли заслонка положение после снятия PWM. Если воздушный поток или пружина возвращают её назад, выход нельзя отключать после достижения цели либо нужна самотормозящаяся механика.
- Для систем, где отказ привода влияет на безопасность вентиляции, механическое безопасное положение должно задаваться конструкцией заслонки или возвратной пружиной, а не только прошивкой.

## Воспроизводимая сборка

Требуемые версии:

- Arduino AVR Boards `1.8.6`;
- Servo `1.2.2`;
- ModbusRtu из `smarmengol/Modbus-Master-Slave-for-Arduino`, commit `38a43f2a6f4996e7b2c863ca5586b049158829ac`.

Установка core и библиотек из Library Manager:

```bash
arduino-cli core install arduino:avr@1.8.6
arduino-cli lib install Servo@1.2.2
```

Драйвер PCA9685 входит в проект и использует стандартную библиотеку `Wire` из AVR core. Внешние библиотеки ServoSmooth и Adafruit PWM Servo Driver не требуются; это также исключает конфликт одноимённых заголовков в ServoSmooth 3.9.

ModbusRtu нужно установить из закреплённого commit в каталог библиотек Arduino:

```bash
git clone https://github.com/smarmengol/Modbus-Master-Slave-for-Arduino.git /path/to/Arduino/libraries/ModbusRtu
git -C /path/to/Arduino/libraries/ModbusRtu checkout 38a43f2a6f4996e7b2c863ca5586b049158829ac
```

Сборка прямого варианта:

```bash
arduino-cli compile --fqbn arduino:avr:nano:cpu=atmega328 ArduinoModbusVentilation
```

Сборка варианта PCA9685:

```bash
arduino-cli compile \
  --fqbn arduino:avr:nano:cpu=atmega328 \
  --build-property 'compiler.cpp.extra_flags=-DSERVO_BACKEND=SERVO_BACKEND_PCA9685' \
  ArduinoModbusVentilation
```

Для Nano со старым загрузчиком замените FQBN при загрузке на `arduino:avr:nano:cpu=atmega328old`. Скомпилированный код для двух вариантов ATmega328P одинаков, отличается протокол загрузчика.

Пример загрузки прямого варианта:

```bash
arduino-cli upload -p /dev/tty.usbserial-PORT \
  --fqbn arduino:avr:nano:cpu=atmega328 \
  ArduinoModbusVentilation
```

На время загрузки может потребоваться отключить RS-485 модуль от `RX`/`TX`, если он мешает работе загрузчика.

## Wiren Board

Шаблон находится в `wirenboard/templates/config-arduino-modbus-servo.json`. В интерфейсе он показывает только режим камина, пять комнатных ползунков, суммы притока/вытяжки и состояние PCA9685. Внутренние физические каналы из интерфейса скрыты. Шаблон одинаков для обоих servo backend.

Для сценариев WB управляющий MQTT-контрол каминного режима — `arduino_modbus_slave_128/Fireplace_mode`. Дополнительный скрипт wb-rules для объединения каналов больше не используется: пары объединены непосредственно в прошивке Arduino.

Параметры устройства:

- port: RS-485 порт контроллера, например `/dev/ttyRS485-2`;
- `baud_rate`: `9600`;
- `data_bits`: `8`;
- `parity`: `N`;
- `stop_bits`: `1`;
- `device_type`: `arduino_modbus_servo`;
- `slave_id`: `128`.

Скрипт `scripts/deploy-wb-template.ps1` сохранён как локальный legacy-инструмент. Он не является частью автоматической установки и не запускается при сборке или проверках проекта.

Перед выпуском на оборудование пройдите [стендовый checklist](docs/hardware-validation.md).
